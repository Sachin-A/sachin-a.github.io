Cloud controllers manage applications better when they adapt to each application’s specifics. That needs application insights, such as call graphs and concurrency models. We propose an Application Insight Plane (AIP) that uses LLM agents to extract these insights once, keep them valid, and share them with every controller.

    7 · Open questions
    What we would like to discuss
    
  
    
    
    Which insights to standardize?
    The few kinds many controllers need, each with one schema, so a provider and a controller built by different teams still fit together.
    
    
    How to keep them valid?
    An insight records the code, configuration and workload it was derived from. When any of those change, the insight has to be checked again, and a controller should fall back to its default when it is stale or uncertain.
    
    
    How to share them safely?
    Give each controller only what it needs. An overload controller needs a thread pool limit, not the source code behind it, and the provider must resist instructions planted in code or logs.
