Status quo
Production controllers, such as autoscalers and load balancers, treat each application as an opaque box. They see only basic signals: request rate, latency and CPU. Section 1
Opportunity
Controllers could manage applications much better if they knew application insights, such as call graphs and concurrency models, and tuned their approach to each application.
Problem
Research prototypes use such insights, but each builds its own extractor. These extractors are tied to one system and break as the application changes, so few of these ideas reach production.
Why now
LLM agents can read code and telemetry, work across frameworks, and run existing tools.
Solution
An architectural change: an Application Insight Plane (AIP) between applications and controllers, where LLM agents
  1. extract each insight once,
  2. keep it valid as the application changes, and
  3. share it with every controller.
Sections 2 to 4
Early results
With AIP’s concurrency insight, Envoy cuts p95 latency by up to 30%. The provider extracted concurrency models for all 100 services with source code, and abstained on the 16 without. Section 5
Open questions
Which insights to standardize, how to keep them valid, and how to share them safely. Section 6

          6. Open questions
          
  
          
    
          Which insights to standardize?
          The few kinds many controllers need, each with one schema.
          
    
          How to keep them valid?
          Record what each insight was derived from, and check it again when that changes.
          
    
          How to share them safely?
          Give each controller only what it needs, such as a thread limit rather than the code.
